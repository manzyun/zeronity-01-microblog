# フロントエンド実装概要

まず、 `gemini/front` ブランチに切り替えて以降の作業を行ってください。

今回は『Meta』社の『Instagram』を模倣したWebサービスの制作を想定していますが、配色は [gruvbox](https://github.com/morhetz/gruvbox) を模するものとします。

なお、レイアウトは『Meta』社の『Instagram』を模して頂いて構いません。加えて、スマートフォン表示の対応も願います。

## 事前情報： バックエンドでのUseCase層の実装

UseCase層の実装の確認を行ってください。現状私個人が考えているUseCaseとして、次を想定しています。なお『ActivityPub』に準拠し、『ユーザー』は『アクター（Actor）』、『投稿』は『ノート（Note）』と読み替えて頂いて構いません：

* ユーザー登録
* ユーザーログイン
  * ユーザーの新規投稿
  * ユーザーの画像添付投稿
  * ユーザーの動画添付投稿
  * ユーザー自身の投稿削除
  * ユーザー自身からの他ユーザーの購読（いわゆるフォロー）
  * ユーザー自身からの他ユーザーの購読解除
* ユーザー削除（退会）

## プレゼンテーション層のコンポーネント作成に当たってのテストコードの作成

保守性・並びに仕様を明確にするため、まずテストコードの実装願います。ここでのテストコードで検証したいものは次の通りです：

* フロントエンドからバックエンドのAPIにHTTPリクエストを送信し、望ましいデータが取得できるか
* バックエンドからの返答を元にコンポーネントが意図通り描画できるか
* バックエンドからの返答が例外であった場合、エラーダイアログを描画するか
  * 例外の際のエラーメッセージとして、リクエストの再送信の案内をするか否か

テストコードが一通り実装でき次第、Gitにてコミット願います。

## プレゼンテーション層の実装

上述のテストコードを元に、フロントエンドの実装を進めてください。
今回、デザインカンプが無い為ボトムアップ方式の実装の方が望ましいと私は考えています。

1. バックエンド側のレスポンスに対応するコンポーネントの作成
2. それらを統合したSingle Page Application（以降：SPA）ないし各ページの作成。望ましいのはSPA
3. フロントエンドの動作確認のテストコード実行

なお、2の工程が終了次第、一度Gitでコミット願います。

# 懸案： フロントエンドとバックエンドの統合テスト及びユーザーが実際に操作するための方法

この指示書を書いている時点では、ユーザーは章題の通り、
「フロントエンドとバックエンドの統合テストの方法」
や、
「ローカル環境でバックエンドを起動し、フロントエンドのファイルをWebブラウザで開き動作確認する方法」
が不明瞭です。

つきましては、 @docs/agent_suggestion_dump.md というファイルにて提案の概要を記載し、もし軽微な対応であればプロジェクトに実装を追加しても構いません。
すなわち、 @back/pyproject.toml や @front/package.json 及び @front/*.config.(ts|js) の改変を行っても構いません。

但し、改変した際のコミットメッセージには、どの様な意図で改変を行ったのかを明確に記してください。
