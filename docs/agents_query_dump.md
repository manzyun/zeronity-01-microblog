まず、 `gemini/back` ブランチに切り替えて以降の作業を行ってください

また、コミットメッセージには接頭辞に "[Vibe]" 、続けて編集内容に応じて次のいずれか複数の接頭辞を加え、コミットメッセージに変更内容の概要を記載し、コミットしてください：

## バックエンドのDomain層の異常系テストコードの作成

現状のテストコードでは、バックエンド側のテストコードに異常系のテストが読み受けられませんでした。

そのため、異常系のテストをまずは制作してください。ここでの異常系とは、
「期待している例外（Exception）が返却されるか」
とします。すなわち、
「今回制作しているプログラムが受け付けない型あるいはクラスを、メソッドや関数の引数に代入した結果」
「今回制作しているプログラムが許容しない値を、メソッドや関数の引数に代入した結果」
が、望ましい例外を送出するかを検証するテストコードを作成してください

なお、この時点で一度コミット願います。

## バックエンドにてUseCase層の実装

続いて、UseCase層の実装を行います。現状私個人が考えているUseCaseとして、次を想定しています。なお『ActivityPub』に準拠し、『ユーザー』は『アクター（Actor）』、『投稿』は『ノート（Note）』と読み替えて頂いて構いません：

* ユーザー登録
* ユーザーログイン
  * ユーザーの新規投稿
  * ユーザーの画像添付投稿
  * ユーザーの動画添付投稿
  * ユーザー自身の投稿削除
  * ユーザー自身からの他ユーザーの購読（いわゆるフォロー）
  * ユーザー自身からの他ユーザーの購読解除
* ユーザー削除（退会）

以降からテストコードや実装に移りますが、上述の箇条書きから類推されるクラス図、ならびに第5正規形まで行ったER図の原本となるMermaidマークアップテキストファイルを、次の順序付き箇条書きの工程を踏んだ上で行ってください：

1. Gitのブランチを `gemini/docs` にチェックアウト
2. @docs/fig_class.mmd を編集（クラス図）
3. @docs/fig_er.mmd を作成（ER図）

なおクラス図に関しては、現存する @back/src/domain/ 配下のスクリプトや、 @back/tests/ 配下のテストコードも参考にしつつ、ドメイン層のクラスについても記載願います。

ここまでの内容を終了次第、Gitにコミット願います。

## テーブル構築のSQLスクリプトファイルの作成

今回のUseCaseやEntityの内容（Repository）あるいは @back/tests/test_repositories.py の内容を鑑みて、リレーショナル・データベースにテーブルを作成するSQLを、@artifacts/ に `00_create_tables.sql` というファイル名で制作してください。

可能であれば、SQLite, MariaDB, PostgreSQL いずれにも用いれるSQLが望ましいです。問題があればそれぞれのDBエンジンに沿ったSQLスクリプトファイルを、次の命名規則に則って作成してください：

`00_create_tables_for_{DataBase Engine Name}`

ここまでの作業を終了次第、Gitにコミット願います。

蛇足にはなりますが、現状サービスのホスティング先候補として私個人は次を挙げます：

* SQLite（『Render』や『Cloud Run』上のPaaSやIaaSの無償枠で今回のプログラムと同梱してホスティング可能であれば）
* TiDB Cloud Starter
* Supabase
* Firebase
